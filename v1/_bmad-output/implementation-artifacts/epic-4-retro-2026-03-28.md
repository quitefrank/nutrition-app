## What Went Well

### Zero status tracking drift
First time in four epics that all stories arrived at the retrospective as `done`. Epics 1–3 all had stories stuck in `review`. Something worked.

### Forward planning: 4.2 pre-built for 4.3
Story 4.2 built the `?recipeId=<uuid>` delete mode into the bulk route before Story 4.3 asked for it. Story 4.3's Task 1 was a confirmed no-op. This pattern — building the interface the next story needs — should be documented and repeated.

### Merge logic (Story 4.1)
The `mergeQuantity` function handles numeric add when both values are parseable, retains the original for "to taste" style quantities. Within-recipe deduplication handled by updating the existingMap after each insert. Clean sequential reasoning.

### Full optimistic update pattern (Story 4.2)
`useCheckGroceryItem` and `useDeleteGroceryItem` implement the complete pattern: cancel-query, set-data, rollback on error, invalidate on settle. No shortcuts.

### Pre-existing TypeScript errors surfaced and fixed (Story 4.4)
`database.ts` was missing `Relationships` arrays required by `@supabase/postgrest-js` 2.x. Fixed in 4.4. These were silently causing `never` type inference issues in grocery and recipe routes.

### 147 new tests, zero regressions
Test infrastructure from Epics 1–3 held completely. No mock-setup rework required.

## Challenges & Learnings

### 1. No visual output during development
Frank expected to see pages render as they were built. The grocery list UI — ingredient view, recipe view, swipe-to-delete, toggle crossfade — shipped without a "here's what it looks like" moment during the epic. This is a process gap, not a code gap.

**Lesson:** Dev workflow should include a visual confirmation step for UI stories before status → `done`.

### 2. Smoke test left as Frank's responsibility
Story 4.4 Task 6 was explicitly marked "HALTED — requires manual browser testing" but the story was closed as `done` anyway. Frank inherited the smoke test checklist.

**Lesson:** Any story with a manual testing checklist must be completed by the dev agent before closing. Smoke test = done criteria, not optional follow-up.

### 3. BUG-02 root cause misdiagnosed
BUG-02 (Scan returning 503) was closed as "Gemini free tier quota exhausted — not a code defect." Investigation during this retrospective revealed the real fix was the urlPattern regex in the service worker (March 24 change log entry: "Fixed urlPattern — regex was tested against full URL, not pathname"). The API key tier was a red herring. Switching to a paid key didn't fix it; fixing the regex did.

**Lesson:** Bug closure requires verification that the stated fix actually caused the resolution — not just correlation with timing.

## Key Takeaways

1. **Forward planning pays off.** Pre-building the interface the next story needs (4.2 → 4.3) eliminated a full task and zero regressions followed. Make this a habit.
2. **Done means done.** Two stories marked done with incomplete work (Task 6 halted, BUG-02 misdiagnosed). Tighten the definition.
3. **Visual confirmation is part of shipping.** Code that renders correctly but is never shown to the product owner isn't shipped — it's deployed.
4. **Zero drift is achievable.** Four epics to get here. Now it's the baseline.
