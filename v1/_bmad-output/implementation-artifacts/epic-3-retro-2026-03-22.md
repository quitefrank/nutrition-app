## Challenges & Learnings

### 1. Status tracking drift — third consecutive epic
Stories 3.2, 3.3, and 3.4 reached this retrospective with `Status: review` in their story files. Same pattern as Epic 1 and Epic 2. Fixed manually during retro prep again.

**Root cause:** No hook enforces the `review` → `done` transition. The dev marks the story review, then nothing fires to prompt the final update.

**Lesson:** Add a check to the code review workflow that updates story file status to `done` on completion. This needs to be a step in `bmad-code-review` or `bmad-dev-story`, not a recommendation in a retro document.

### 2. Story 3.6 fell through the cracks
USDA nutritional data at save time was a deliberate Epic 3 scope addition agreed in the Epic 2 retro. The retro prep task "add Story 3.6 to epics.md" was marked ✅ Done. It was not done. Story 3.6 was never created. Every recipe currently shows "Nutrition unavailable" — the NutritionPanel is built and waiting but has no data.

**Lesson:** Retro prep tasks need the same verification standard as story amendments. "I think I did it" is not verification. Check the file.

### 3. Stories 3.4 and 3.5 overlapped mid-epic
Story 3.4's completion notes flag "12 pre-existing failures in page.test.tsx and route.test.ts from parallel Story 3.5 prep work." At the point 3.4 was being tested, 3.5 was already modifying shared files. The 12 failures resolved when 3.5 completed, but the test suite was red mid-epic.

**Lesson:** If a story modifies shared files, that work should not begin until the previous story's tests are green. Parallel development on the same file tree creates transient failures that obscure real issues.

## Key Takeaways

1. **Document-only rules don't fire.** Three epics of status drift. The fix is a hook in the workflow skill, not another action item in a retro document.
2. **Verify completion claims against files.** Story 3.6 was marked done in the Epic 2 retro prep. It wasn't. Check the file.
3. **Parallel development on shared files creates red test suites.** Stories 3.4/3.5 overlapped on route.ts and page.tsx. Wait for green before starting the next story on the same files.
4. **The spec is a floor, not a ceiling.** Story 3.4's dev agent improved on the spec. That's good. Review it, capture it, carry the pattern forward.
