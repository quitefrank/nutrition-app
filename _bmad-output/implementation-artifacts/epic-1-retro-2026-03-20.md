## Challenges & Learnings

### 1. TypeScript error carried across two stories
A `framer-motion` ease type mismatch in `bottom-sheet.tsx` was introduced in Story 1.2. Both Story 1.3 and Story 1.4 noted it as "pre-existing, not this story's scope" and moved on. The error was inherited into Epic 2.

**Resolution:** Fixed live during this retrospective — `ease: 'easeIn' as const` on the exit transition. All 62 tests remain green.

**Lesson:** When a story notes a pre-existing issue and explicitly defers it, it needs to land somewhere concrete (action item, tech debt ticket) rather than just a comment in dev notes. "Not my scope" without a handoff is a drop.

### 2. Story 1.2 status out of sync
Story 1.2's file header showed `Status: review` while sprint-status.yaml showed `done`. The two sources of truth were mismatched.

**Resolution:** Fixed live during this retrospective — story file updated to `Status: done`.

**Root cause:** A sandbox limitation prevented automated discovery of the file during retro prep, which surfaced the discrepancy. In normal operation this would have gone unnoticed.

**Lesson:** SM should cross-check that story file status matches sprint-status before closing a story.

## Epic 2 Preparation

### Gemini API Spike — Completed During Retro

Tested Gemini 3 Flash Preview against a real restaurant menu image (Joey's — starters and steaks menu).

**Results:**
- Clean JSON output, followed prompt structure exactly
- 20 dishes identified from a single image scan
- Calorie estimates populated for all dishes
- Descriptions accurate and useful

**Critical finding for Story 2-1:**

Gemini menu scans return `name`, `description`, `calorieEstimate` — but **not a structured ingredient list**. Your existing `DishResult` type expects `ingredients: IngredientResult[]`. This mismatch must be resolved in Story 2-1 spec before implementation:

- Option A: Menu scan returns `ingredients: []` (empty), populated later via a separate enrichment call
- Option B: `DishResult` gets a `menuScan` variant that makes `ingredients` optional

**Decision required:** During Story 2-1 story creation, SM must capture this as an explicit open question for Frank to resolve before Amelia implements.
